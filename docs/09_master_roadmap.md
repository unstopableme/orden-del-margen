# Specification: Master project documentation roadmap

**System module:** Central documentation / structural asset map  
**Status:** Offline documentation index; implementation deferred  
**Tracking scope:** Directory indexing only; no project-management runtime

## 1. Purpose and status vocabulary

This file records documentation presence and review boundaries. A checked item
means only that the Markdown file exists in this repository; it does not mean
the described feature is adopted, implemented, tested, deployed, or legally
approved.

| Marker | Meaning |
| --- | --- |
| `[x]` | File exists |
| `[ ]` | Reserved filename or requested document is not present |
| `Proposal` | Offline design content; no runtime authority |
| `Adopted design` | Approved direction with implementation still deferred |
| `Implemented` | Runtime artifact exists; verification status remains separate |

`TEST_MANIFEST.md` is authoritative for executable test status. This roadmap
must not convert documentation review into test evidence.

## 3. Core architecture and policy documents

The repository also contains unnumbered architecture, economy, decision,
snapshot, participant-verification, administration, materials, implementation,
and test documents. Their presence and status are discoverable from the actual
`docs/` directory and README links. This roadmap does not restate them as
implemented features.

## 4. Global structural invariants

- Candidate gameplay fees and ordinary utility-asset costs use `$DONCELLA`.
- “Bronze currency” is an alias for `$DONCELLA`, not a separate balance; the
  Bronze mining plot remains a distinct land tier.
- `$MARGEN` is not rejected. It remains the proposed ownership-related/reward
  asset governed by the economy and decision documents. Unapproved `$MARGEN`
  gameplay fees, skill costs, quest fees, and loot-processing fees are excluded.
- Weekly reward periods run from Sunday 00:00 UTC inclusive to the following
  Sunday 00:00 UTC exclusive. This is not a universal scheduler for every
  gameplay or UI system.
- Participant identity, authenticated accounts, primary-account designation,
  characters, community profiles, and faction choices are separate concepts.
- UI layouts, lore, localization fallbacks, and candidate manifests never
  replace authoritative service/database state.
- Documentation-only review does not authorize runtime hooks, database writes,
  network calls, simulations, or tests.

## 5. Maintenance rules

When adding or renaming a numbered sheet:

1. verify the file actually exists before checking it here;
2. add or update its README link;
3. record any executable validation only in `TEST_MANIFEST.md`;
4. preserve proposal/adopted/implemented distinctions;
5. avoid embedding personal data, credentials, balances, or production IDs in
   examples; and
6. do not describe local previews or Markdown rendering as system validation.

## 6. Offline boundary

This roadmap performs no discovery at runtime and is not generated by an active
project-management process. No implementation, database initialization,
simulation, or test is authorized by this file.
